## Что сделано в этой сессии

- Найдена настоящая причина «ahead N при чистом дереве»: пуш по прямому URL
  (`git push <URL> main`) не обновляет трекинг-ссылку `origin/main`.
  Доказано изолированным опытом на временном клоне. Обычный `fetch` чинит
  симптом до следующего URL-пуша.
- Проверены оба репозитория: Elite-Deep (`13e6efe` везде, дерево чистое, `fsck`
  чист) и GrimoireHub (пробный коммит убран с remote, `63dc373` везде,
  содержимое не тронуто).
- Удалены `scripts/sync-refs.sh` (лечил следствие, создавал гонку) и временная
  копия дерева в системном Temp. Журнал проекта несёт верную причину.
- Починены три обёртки в домашнем каталоге WorkBuddy: сопоставление ссылок
  теперь срезает credentials (ссылка с токеном ловится, чужая пропускается,
  проверено без сети). Внимание: обёртки НЕ подключены (поле env в настройках
  пусто) — это ещё предстоит сделать.
- В скилле проверки доступа вырезан раздел с неверной теорией про перехват и
  ручной перезаписью packed-refs, заменён снятым диагнозом.

## Команды для проверки

```bash
git status -sb
git rev-parse HEAD; git rev-parse origin/main; git ls-remote origin refs/heads/main
```

Все три SHA должны совпасть, статус — чистый. Если `status` показывает `ahead`
при чистом дереве — смотри, каким способом пушили (по имени или по URL),
а не копай `.git`.
